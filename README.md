## SQL-практика

Нужен Python 3; используется стандартный модуль SQLite:

~~~sh
python3 sql/run.py
~~~

Скрипт создаёт временную базу в памяти, загружает синтетические данные и выполняет шесть диагностических запросов. База не является частью API-стенда: это отдельное упражнение по SQL.

Регрессионные тесты сравнивают полные результаты Q1–Q6 с ожидаемыми строками на синтетических данных. Для Q4 дополнительно проверяются продукты без обращений и только с закрытыми обращениями:

~~~sh
python3 -m unittest discover -s sql -p 'test_*.py' -v
~~~

[GitHub Actions](https://github.com/Decl1s/support-qa-case-study/actions/workflows/sql-checks.yml) запускает эти тесты при каждом push и pull request. Достаточно стандартной библиотеки Python и SQLite, внешний сервер БД не нужен. Проверки фиксируют результаты Q1–Q6 на заданных данных и два граничных случая Q4; полное покрытие SQL и корректность документов они не подтверждают.


## Что показывает кейс

Переход от сообщения «не работает» к описанию условий, ожидаемого и фактического поведения; граничные значения; трассировка требования → тест → дефект; диагностика по данным и формулировка проверяемого критерия исправления.
