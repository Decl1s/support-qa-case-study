# BUG-001: API принимает размер больше допустимого

Тип: намеренно внесённый учебный дефект. Не ошибка AV SOFT и не результат проверки чужого сервиса.

Компонент: POST /jobs. Требование: sizeKb от 1 до 4096 включительно.

Среда: локальный FixtureServer; режим demoBug=true. Серьёзность: Major в рамках учебного контракта — нарушено ограничение размера. Приоритет: P1 для упражнения, поскольку проверяется основной ввод.

## Воспроизведение

1. Открыть java-api-testing-lab.
2. Выполнить `mvn -DdemoBug=true -Dtest='JobsApiTest#invalidSize' test`.
3. Посмотреть варианты 4097 и 2147483647 в отчёте Surefire.

Запрос: POST /jobs, X-Api-Key: demo-token, Content-Type: application/json.
Тело: `{ "filename": "a.txt", "sizeKb": 4097 }`.

Ожидается: 422, error=validation_error; задание не должно приниматься.
Фактически: 201, задание создано со статусом QUEUED.
Воспроизводимость: детерминированная, при включённом demoBug.

Диагноз: в режиме demoBug отключена проверка `size.asLong() > 4096`.
Проверка устранения: отключить demoBug и выполнить обычный `mvn test`; 4097 и максимальное int должны дать 422, а 4096 — 201. Это демонстрация чувствительности тестов к дефекту, а не полноценная история исправления production-ошибки.

Артефакты запуска: [результаты в Java-репозитории](https://github.com/Decl1s/java-api-testing-lab/blob/main/docs/test-results.md).
